# 지원서 분석·초안 계약

## 탭 잠금

읽기 전용 분석을 시작할 때 다음 값을 기록한다.

- Chrome `provider_tab_id`
- 현재 URL과 origin
- 페이지 title
- 회사와 직무
- 주요 폼 레이블·필드 구조로 만든 SHA-256 `page_fingerprint`
- 화면 캡처별 SHA-256과 구조화된 시각 관찰

다음 단계 전에 이 값들이 같지 않으면 기존 세션을 중단하고 새로 분석한다. 사용자 계정, 쿠키, 비밀번호는 기록하지 않는다.

## 필드 구조

필드마다 가능한 범위에서 다음을 수집한다.

- `field_id`, section, label, type
- required, min_length, max_length, length_unit
- placeholder, helper_text
- select/radio 선택지
- iframe 경로
- 파일 입력의 accept, multiple, 크기 안내
- 현재 값 존재 여부와 오류 문구

현재 값의 원문은 MCP 세션에 저장하지 않는다.

## 시각 교차검증

- 첫 화면과 필요한 폼 구역만 최소한으로 캡처한다.
- 캡처는 필드 그룹, 필수 별표, 글자 수 카운터, 비활성/선택 상태, 오류·경고, 진행 단계, 오버레이, 업로드 상태를 확인하는 데 사용한다.
- 색상·아이콘·위치·글꼴만으로 상태를 확정하지 않는다. DOM 속성, 접근성 이름, 안내 문구 또는 오류 텍스트와 교차검증한다.
- 각 관찰에는 scope, kind, severity, confidence, DOM 교차검증 여부, screenshot SHA-256을 남긴다.
- 캡처에 보이는 기존 개인정보 값은 필드 상태 확인에 필요한 경우가 아니면 전사하거나 세션에 저장하지 않는다.
- 화면과 DOM이 충돌하며 필수 여부·제한·오류 상태에 영향을 주면 `blocking`으로 기록한다.

## 답변 계약

- 사실 항목은 충돌 없는 구조화 프로필 또는 검증된 Notion Claim 근거를 사용한다.
- 서술 항목은 로컬 문서나 Notion 스냅샷의 하나 이상의 `verified` Claim을 연결한다.
- 원문에 없는 수치, 기간, 회사, 역할, 성과를 생성하지 않는다.
- 같은 Claim을 여러 자기소개서 항목에 반복하면 검토 이슈로 남긴다.
- `unsupported_claims`가 있으면 통과 상태로 표시하지 않는다.
- 글자 수 단위가 `utf8_bytes`이면 UTF-8 바이트로 계산하고, 그 외에는 문자 수로 계산한다.

## 직접 입력 계약

- `입력해줘`, `채워줘`, `직접 입력`처럼 현재 폼에 대한 명시적 요청이 있을 때만 직접 입력 모드를 사용한다.
- 입력 전에 정확한 탭과 필드별 값을 확정하고 Browser/Computer Use 확인 정책을 따른다.
- 확인이 필요하면 사이트와 입력 데이터를 한 문장으로 한 번만 묻는다. 같은 값과 목적지에 대한 확인을 반복하지 않는다.
- 전역 Claim이 아직 `review_required`여도 사용자가 해당 실행의 정확한 필드 값을 명시적으로 확인하면 그 실행에서만 사용할 수 있다. Claim 상태는 자동 변경하지 않는다.
- Chrome의 의미 기반 입력을 우선하고, 입력·클립보드 브리지가 실패하면 같은 Chrome 탭에 한해 Computer Use로 전환한다.
- 입력 후 회사명, 기간, 직급·직책, 선택값, 본문, 바이트 카운터를 다시 읽어 초안과 일치하는지 확인한다.
- 임금과 민감·법적 필드는 명시된 근거와 별도 승인 없이는 비워 둔다.
- 총 근무기간처럼 저장을 발생시키지 않는 파생 계산은 입력 확인 후 실행할 수 있다.
- 입력된 탭은 사용자 검토를 위해 열어 둔다.

## v0.4 중단선

직접 입력은 허용하지만 작성완료, 저장, 다음 단계, 첨부, 동의 체크와 제출은 별도 요청과 필요한 확인 전까지 범위 밖이다.
