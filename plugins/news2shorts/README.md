# news2shorts

Codex에서 뉴스 링크 또는 오늘의 뉴스 후보를 검증하고 한국어 YouTube Shorts 제작 패키지와 로컬 MP4를 만드는 MVP 플러그인입니다.

## 포함 기능

- NAVER API HUB·NAVER News·뉴스픽 공개 뉴스 화면과 원문 웹 검색을 결합한 후보 탐색
- 정치·공공 책임과 생활비·주거·안전·건강·교육·노동·권리·개인정보·공공서비스를 함께 보는 시민 민감도 기반 핫이슈 점수
- 서로 다른 공개 커뮤니티 2곳 이상에서 같은 검증 뉴스가 관찰될 때만 적용하는 소규모 발견 신호
- 뉴스 프로젝트와 출처·팩트·권리 매니페스트 초기화
- Codex 기반 후크·재후킹 대본, 스토리보드, 상업 이용 가능한 웹 이미지·영상 우선 검색, 이미지 생성 보완 워크플로
- 절차 요약보다 실제 모순·시청자 손해·끝까지 회수할 반문을 먼저 고정하는 이슈 렌즈 검수
- 제주도 같은 검증된 실제 지역명, 중앙 실명 인물의 사진 권리·사생활 상태, 확인된 행위·누락과 시민 피해의 책임 연결을 프로젝트 템플릿에 기록
- 반응 밈·대비 합성·영향 사진·근거 클로즈업·동작 증거 중 하나를 권리 안전한 핵심 시선 장치로 지정
- 새 영상 장면의 60% 이상을 권리·기사 연관성을 확인한 실제 사진·영상으로 구성하고 실제 뉴스 사진 최소 1장 필수
- 새 프로젝트에서 현재 뉴스 기사와 로그인 없는 공개 커뮤니티의 직접 관련 이미지를 일반 스톡·생성 이미지보다 먼저 찾는 시각자료 우선순위
- 권리 미확인 뉴스·커뮤니티 이미지는 출처·사생활 검토 후 무배지 로컬 검토본에만 사용하고 게시 전 확인 또는 교체
- 새 프로젝트의 모든 장면을 `ko-KR` 한국 배경으로 제한하고 해외 표지판·경찰복·차량 번호판·도로·건축·상점 문구가 보이는 자산 차단
- 생성 보완은 현재 한국 생활환경을 자연광·현실 재질로 표현하는 `korean-editorial-realism`만 기본 허용
- 최근 24시간·최근 6시간 복수 출처 확산을 별도로 확인하는 `hot-real-news` 후보 모드
- 권리 미확인 공개 이미지를 출처·권리 미확인 상태로 기록하고 로컬 검토본까지만 허용하는 `unreviewed` 자산 경계
- 검토한 실제 뉴스 이미지를 선화로 변환해 별도 Whiteboard Shorts 프로젝트와 로컬 draft MP4를 만드는 `whiteboard` 시각 모드
- 핵심 기업이 실명으로 등장하면 첫 주요 언급에 권리 승인 로고 또는 실제 기업 이미지 필수
- 생성 이미지를 기본 720x1280 이하로 축소하는 프로젝트 자산 최적화
- 생성 이미지 왜곡·중복 물체·깨진 글자 등을 확인하는 육안 품질 승인 게이트
- Pillow와 FFmpeg 기반 720x1280 영상 렌더
- Typecast 공식 인기 캐릭터군 기반 콘텐츠 적합 보이스 자동 선택과 CTA가 없을 때 본문 전체를 한 번에 읽는 `continuous-flow` 전달
- 키체인 접근 제한과 실제 미설정을 구분하는 Typecast 진단·복사 가능한 설정 명령
- 화면 표시 없는 미리보기 상태 기록 및 최종 렌더 승인 게이트
- 새 프로젝트를 12-35초 `quick-reveal` 하나로 고정하고, 본문 Typecast 1회 또는 중간 CTA 앞뒤 2회 생성·구절별 하드 컷·연속 오디오 재결합을 적용하는 `continuous-flow`
- 배지·상단 장식·배경 비침 없이 확인된 답·의미·마지막 붙잡기를 분리해 크게 보여주고 후크 회수 문구와 안전 여백을 보장하는 불투명 단일 편집형 결론 카드와 장면 하단의 작은 `뉴스 출처` 표시
- 앞 장면의 완성된 자막·금액을 결론 카드에서 반복하지 않고 새 행동·조건·결과로 마무리하는 결론 중복 검증
- 게시일에 따라 틀리는 `다음 달부터`·`오늘부터`와 출처 없이 즉시 견인을 단정하는 문구 경고
- 질문·반전·응답이 다음 장면으로 이어지는 대화형 내레이션 규칙
- 기존 `standard`와 친구에게 설명하는 `cc-helper-conversational` 말투 선택
- 대사의 특정 강조 구간에만 작동하는 `zoom-in`·`zoom-out`, 기본 정지 화면, 문서 장면 `none` 모션과 초점 좌표
- 비민감 맥락·재후킹 장면의 상업 이용 가능한 반응 밈과 사용 권리 검사
- v16 신규 렌더는 첫 프레임부터 본문과 좌상단 뉴스한면 로고를 표시하고, v15 이하 프로젝트만 저장된 3.15초 공통 인트로 유지
- 명시적으로 선택할 수 있는 8~14초 무내레이션 `visual-first`와 렌더러 생성 무보컬 BGM
- 결론 뒤 구독·좋아요형과 주제별 댓글형을 안전하게 자동 선택하는 v16 기본 2초 공통 CTA 테일
- v17 continuous-flow에서 사용자가 `auto`, `enabled`, `disabled`로 선택하는 하단 YouTube 채널 영역 유도형 중간 CTA와 중복 없는 0.8초 브랜드 마감
- 인트로와 뉴스 본편 사이의 0.25초 전환·오디오 교차와 본편 내부 하드 컷
- 기존 `broadcast-card`, `classic-card` 스타일 호환
- 영상 해상도·길이·오디오·이미지·클립 권리 정적 검사
- Typecast 예상 길이 사전 검사와 실제 렌더 길이·장면 유지 시간 차단
- Typecast 문장 내부 호흡은 보존하고 음성 시작·종료 외곽 무음만 정리하는 결론·CTA 경계 개선
- `--no-tts` continuous-flow 검토본에서 글자 수 재분배 대신 스토리보드 요청 장면 길이를 그대로 사용하는 무음 타이밍
- 실제 사진·영상 60% 미만 최종 차단과 생성 시각자료 40% 초과·3장면 연속 사용 경고
- 서로 다른 권리 승인 장면 이미지 2~3장을 합성한 고대비 720x1280 `thumbnail.jpg` 자동 생성
- CapCut Desktop/Web·Vrew 호환 `editable.mp4`, UTF-8 SRT, 장면별 MP4/WAV, 투명 PNG 오버레이, 타임라인 CSV 자동 생성
- 영상 결과와 함께 태그 2개가 자동 보완된 질문형 제목, 제목을 반복하거나 해시태그를 넣지 않은 답·근거형 설명, 태그·썸네일·재생목록·시청자층·공개 상태·고정 댓글 패키지 제공
- 뉴스 수집 후 주제와 결과물 범위를 확인하는 사용자 선택 게이트

YouTube 업로드, DB, 웹 UI, MCP 서버는 포함하지 않습니다.

## 태그만으로 시작하기

Codex에서 `@news2shorts` 플러그인 태그만 입력해도 오늘의 뉴스 후보 수집을 바로 시작합니다. 별도의 요청 문구가 없으면 NAVER API 사용 여부와 관계없이 NAVER News와 뉴스픽을 후보 발굴 범위에 포함하고, 원문 웹 검색과 Computer Use의 읽기 전용 화면 확인을 더해 현재 한국 뉴스를 교차검증합니다. 뉴스픽은 헤드라인·표시 언론사·시간만 후보 신호로 사용하고, 원문과 독립 출처를 찾지 못하면 후보에서 제외합니다. 정치·공공 책임 후보와 시민의 돈·주거·안전·건강·교육·노동·권리·개인정보·공공서비스에 영향을 주는 후보를 별도 검색 레인에서 확인합니다. 공개 커뮤니티가 접근 가능하면 성격이 다른 2곳 이상을 읽기 전용으로 확인하되 이슈 발견 신호로만 사용합니다. 검증된 후보 10개와 추천 1개를 한 번에 제시한 뒤 사용자의 주제와 제작 범위 선택을 기다립니다. 새 제작은 항상 `quick-reveal + continuous-flow`로 진행합니다.

## 사용자 확인 흐름

뉴스 URL이나 단일 주제가 없으면 플러그인은 오늘의 후보를 정확히 10개까지 수집·교차검증한 뒤 제작을 멈추고 사용자에게 주제를 확인합니다. 검증 후보가 10개보다 적으면 탐색을 계속하며, 외부 접근 제한으로도 채우지 못하면 `후보 조사 미완료: N/10`으로 표시하고 제작을 진행하지 않습니다. 추천 후보는 표시하지만 자동으로 선택하지 않습니다.

후보 10개는 `1`부터 `10`까지 한 목록으로 모두 표시합니다. 사용자는 `1번, 영상까지`처럼 주제 번호와 결과물 범위를 함께 답할 수 있습니다. 기본 사용자 선택창은 주제가 정해진 뒤 결과물 범위를 확인할 때 사용합니다.

결과물 범위를 미리 지정하지 않았다면 다음 중 하나를 선택하도록 요청합니다.

1. 조사: 출처, 교차검증 요약, 팩트 시트
2. 대본: 조사 결과와 후킹 후보, 최종 쇼츠 대본
3. 이미지: 대본과 스토리보드, 생성·수집 이미지 파일, 권리 기록
4. 영상: 앞 단계 전체와 음성, 미리보기 MP4, 렌더 보고서, 영상과 별도로 생성한 질문형 썸네일, 제목·설명·태그·재생목록·시청자층·공개 상태·고정 댓글

기본 선택창에서는 먼저 `영상까지`, `이미지까지`, `텍스트까지만`을 보여줍니다. `텍스트까지만`을 선택하면 `대본까지`와 `조사만` 중 하나를 한 번 더 확인합니다. 대본 이상은 검은 상단의 크고 굵은 중앙 정렬 헤드라인·노란 강조색·구절별 증거 교체·하단 윤곽 자막을 쓰는 `quick-reveal + continuous-flow`로만 제작합니다. 복잡한 사건도 한 가지 질문과 명확한 답으로 좁혀 12-35초 안에 전달합니다. 이미 확인된 항목은 다시 묻지 않습니다. 단, 민감 뉴스와 최종 영상은 사실·권리·합성 이미지 메타데이터 상태에 따라 추가 승인이 필요할 수 있습니다.

`standard` 말투가 기본입니다. `cc_helper 말투`를 요청하면 사실 근거·truth guard·민감 뉴스 제한은 유지하고 문장 종결과 연결만 친구 설명형으로 바꾸는 `cc-helper-conversational`을 사용합니다. 출처에 없는 의도·과장·속어·비난·여론은 추가하지 않으며, 원본 영상 대사는 그대로 보존합니다.

## 후킹과 포맷

뉴스 요약형 도입은 사용하지 않습니다. 새 프로젝트는 먼저 `핵심 모순`, `시민·소비자 이해관계`, `첫 훅 질문`을 기록합니다. 첫 화면과 첫 내레이션은 모두 구체적인 질문으로 시작하며, 허용·거부·재검토·발표 같은 절차보다 그 결정이 시민의 비용·안전·생활·권리에 미치는 영향을 묻습니다. 예를 들어 사실관계가 뒷받침할 때 `욕조 허용안 재검토`보다 `좁은 방은 그대로인데, 욕조 하나면 주거 개선인가요?`처럼 대상과 남은 문제를 함께 드러냅니다.

플러그인은 세 개의 질문형 후크 후보를 만든 뒤 반직관, 결과 선공개, 비교 반전, 변화 영향, 숫자 격차, 이슈 긴장 중 사실에 맞는 전개를 붙입니다. 질문은 구체적인 시민 영향을 포함해야 하며 `이게 맞나?`처럼 대상 없는 문구는 통과하지 못합니다. 이후 근거·반전·결론이 첫 질문을 회수합니다. 피해자를 자극하거나 확인되지 않은 책임을 암시하지 않으며, 재미는 시민이 품을 법한 의문, 반전, 대비, 증거와 전개 속도로 만듭니다.

지역이 사건 이해의 핵심이면 첫 맥락 장면에서 `제주도`, `제주경찰청`처럼 확인된 실제 이름을 화면과 음성으로 밝힙니다. 중앙 실명 인물은 실제 사진의 재사용 권리와 사생활 필요성을 먼저 검토하고, 사용·사생활 제외·권리 장애 중 하나를 기록합니다. 가족 제공 사진·실종 공고·SNS·언론 사진은 공개되어 있어도 자동 재사용하지 않으며, 다른 실제 인물의 자료사진은 `사건 당사자 아님`을 표시합니다. 거짓 보고나 관리 누락처럼 근거가 있는 책임 이슈는 구체적 행위와 시민 피해·신뢰 훼손을 주장 ID와 장면으로 연결해 가장 강한 임팩트 구간에 배치합니다.

새 퀵리빌은 `hook_stake`에 첫 숫자나 주장이 왜 중요한지 출처가 있는 한 문장으로 기록합니다. 첫 화면과 첫 대사는 그 의미를 직접 보여주고 첫 장면은 근거 주장과 연결됩니다. 따라서 `월 3,300만원`처럼 숫자만 띄우는 훅은 최종 검수를 통과하지 못하며, `월 3,300만원에도 의료 공백`처럼 실패한 기대·공공 영향·비용·격차가 함께 보여야 합니다. 논란성은 확인된 모순과 책임 질문으로 강화하되 출처에 없는 분노·비난·여론은 만들지 않습니다.

`의안 2217144`, 사건번호, 문서번호처럼 시청자가 들을 필요가 없는 긴 행정 식별번호는 후크·자막·결론·내레이션에서 `해당 의안`, `해당 사건`처럼 자연어로 바꿉니다. 렌더러도 화면 텍스트와 로컬·Typecast 음성을 만들기 전에 같은 처리를 적용합니다. 정확한 번호는 검증을 위해 `sources.json`, `fact-sheet.json`, 권리·출처 기록에만 유지합니다.

- `quick-reveal + continuous-flow`: 12-35초. 한 가지 비교·반전·정답을 빠르게 회수합니다. 기본은 본문 전체 음성을 한 번에 생성합니다. 중간 CTA가 있으면 CTA 경계를 먼저 고른 뒤 앞 본문과 뒤 본문을 각각 완전한 Typecast 요청으로 생성해 말하는 중간을 자르지 않습니다. 장면은 대사 구절에 맞춰 하드 컷으로 교체합니다. 과거 `fact-stack`과 `story-explainer` 프로젝트는 다시 열거나 렌더할 때만 호환됩니다.

## 환경 확인

```bash
python3 scripts/news2shorts.py doctor
```

필수 항목은 Python 3, Pillow, FFmpeg, FFprobe, 한글 폰트와 영상·음성이 들어 있는 720x1280 공통 인트로 자산입니다. `doctor`는 공통 인트로 상태와 Typecast API 키 설정 여부·자동 선택 후보를 표시하되 키 값은 노출하지 않습니다. Codex 샌드박스가 macOS 키체인 조회를 막으면 `typecast_keychain_check_limited: true`와 재확인·설정 명령을 함께 표시하며, 이 상태를 실제 키 미설정으로 단정하지 않습니다.

## Typecast API 설정

Typecast는 기본 TTS 제공자입니다. 새 프로젝트와 기존 설정 없는 프로젝트는 `narration_voice.mode: "auto"`로 동작합니다. 공개된 수치형 사용량 1위 자료는 없으므로 임의의 1위를 만들지 않고, Typecast가 공식적으로 소개한 인기 캐릭터 Top 5인 다은·서현·필재·문정·강일 안에서 보이스를 자동 선택합니다.

- 일반 자동 프로젝트: 강일 80%, 다은 20%
- 같은 프로젝트를 다시 렌더하면 같은 보이스를 유지하는 프로젝트 고정 10개 버킷 방식
- 민감 뉴스: 서현
- 내레이션 장면 절반 이상이 사용법·대처·절차인 경우: 문정

선택 결과와 이유, `official-popular-top5+content-fit+stable-80-20` 전략, 인기 후보 근거, 공식 출처, 적용 분포와 버킷은 `project.json`과 `render-report.json`에 기록됩니다. 명시적인 고정이 필요할 때만 `--typecast-voice Kangil`처럼 후보 이름을 지정합니다. 80:20은 공식 사용량 순위가 아니라 강일을 메인으로 사용하는 플러그인의 제작 분포이며 바이럴 성과를 보장하지 않습니다. API 키는 저장소나 프로젝트 JSON에 저장하지 않습니다.

새 continuous-flow 프로젝트는 CTA가 없으면 본문 전체를 Typecast 한 요청으로 합성하고, 중간 CTA가 있으면 CTA 앞뒤 본문을 두 요청으로 합성하므로 모든 장면의 `voice_delivery`를 `auto`로 유지합니다. CTA는 완전한 두 요청 사이에만 들어가며 글자 수 비례로 자른 WAV 중간에는 넣지 않습니다. 강조는 짧은 문장 호흡과 근거가 있는 반전 문구로 설계합니다. 기존 장면형 프로젝트만 필요할 때 `verdict` 또는 `contrast`를 유지할 수 있습니다. 새 결론은 확인된 답 뒤에 앞 문구를 반복하지 않는 `payoff_punch`를 크게 보여주고, 음성에서도 그 핵심 표현을 별도 박자로 말합니다.

macOS에서는 다음 명령을 최초 한 번만 실행합니다. macOS 키체인이 숨김 입력을 열며, 같은 명령을 다시 실행하면 기존 키를 교체합니다.

```bash
python3 scripts/news2shorts.py configure-typecast
python3 scripts/news2shorts.py doctor
```

이후 렌더러는 매번 키체인에서 키를 직접 읽으므로 터미널이나 Codex 앱을 다시 시작해도 재설정할 필요가 없습니다. `doctor`의 `typecast_api_key_source`가 `keychain`이면 설정된 상태입니다. 키체인이 잠겨 있으면 macOS가 잠금 해제를 요청할 수 있습니다.

`doctor`에서 `typecast_api_key_configured: false`가 나오면 함께 출력되는 `typecast_setup_guidance`를 확인합니다. `typecast_keychain_check_limited: true`면 키가 없는 것이 아니라 현재 실행에서 키체인 조회가 막힌 것일 수 있으므로 사용자 터미널에서 안내된 `doctor` 명령을 다시 실행합니다. 그때도 키가 없을 때만 출력된 `configure-typecast` 명령을 최초 한 번 실행합니다. Typecast를 요청한 영상은 이 확인 없이 로컬 TTS로 자동 대체하지 않습니다.

CI나 macOS가 아닌 환경에서는 `TYPECAST_API_KEY` 환경변수를 사용하며, 환경변수가 있으면 키체인보다 우선합니다. `.env.example`은 변수 이름을 보여주는 예시일 뿐이며 렌더러가 `.env` 파일을 자동으로 읽지는 않습니다.

Typecast 연결은 별도 SDK 없이 공식 `POST /v1/text-to-speech` API를 직접 사용합니다. `ssfm-v30`, 자동 선택 Voice ID, 한국어, Smart Emotion, 장면 간 앞뒤 문맥, 1.05배 속도, -14 LUFS WAV가 기본값입니다. 속도만 바꾸려면 `--typecast-tempo`를 사용합니다.

## NAVER API HUB 설정

오늘 뉴스 후보 자동 탐색은 다음 환경 변수를 사용합니다.

```text
NAVER_API_HUB_CLIENT_ID
NAVER_API_HUB_CLIENT_SECRET
```

키를 저장소, 프로젝트 JSON, 명령 인자 또는 로그에 기록하지 마세요.

```bash
python3 scripts/news2shorts.py discover --output ./candidates.json
```

`discover`는 기본적으로 현재 작업 폴더의 `./projects`를 먼저 읽어 이미 생성했거나 진행한 news2shorts 주제를 제외합니다. `project.json`의 제목·주제·이슈 초점과 `sources.json`의 원문·교차검증 기사 URL 및 제목을 함께 비교하므로, 언론사나 헤드라인이 바뀐 동일 사건의 후속 기사도 새 후보로 다시 제시하지 않습니다. 초안, 수정 대기, 검토 렌더, 완료 상태를 모두 이미 다룬 주제로 봅니다. 결과 JSON의 `excluded_used_topics`에서 제외된 후보와 기존 프로젝트의 연결 근거를 확인할 수 있습니다. 프로젝트 이력이 다른 위치에 있을 때만 다음 옵션을 사용합니다.

```bash
python3 scripts/news2shorts.py discover \
  --project-history-root /path/to/projects \
  --output ./candidates.json
```

실제 최신 뉴스 확산을 더 엄격히 볼 때는 최근 24시간 안에서 최근 6시간 내 서로 다른 보도 출처 2곳 이상이 확인된 후보만 남깁니다.

```bash
python3 scripts/news2shorts.py discover --hot-real-news --output ./candidates.json
```

`discover`는 먼저 시민 영향 관문을 적용합니다. 제목과 요약에서 영향받는 집단과 직접 비용·안전·권리·공공서비스 결과가 함께 확인된 후보만 `candidates`에 남기고, 조직 내부 성과급·임원·주주 이해관계나 시민 결과가 없는 절차·정치 공방은 이유와 함께 `rejected_candidates`로 분리합니다. 최종 추천 전에는 원문 근거로 `누가 무엇을 얼마나 잃거나 위험해지는가`를 한 문장으로 작성해야 합니다. 이후 최근 6시간의 독립 보도 확산, 출처 다양성, 시민 민감도, 정치·공공 책임성, 검증 준비도를 분리해 기록합니다. 점수는 후보 검토 순서일 뿐 조회수 예측이나 국민 여론 측정값이 아닙니다. 공개 커뮤니티 신호를 확인한 경우 글 본문·댓글·작성자·개인정보를 저장하지 않고 `title`, `community`, `url`만 담은 최대 50개의 임시 JSON을 `--community-signals`로 전달할 수 있습니다. 한 커뮤니티는 가산하지 않으며, 서로 다른 2곳 이상에서 관찰되고 독립적으로 검증된 뉴스 군집과 제목이 일치할 때만 최대 5점을 부여합니다.

후보 수는 10개로 고정됩니다. CLI는 `--candidates 10`만 허용하고, 검증 후보가 10개 미만이면 `discovery_complete: false`, 부족한 수를 `candidate_shortfall`에 기록하며 종료 코드 2를 반환합니다. 이때 시간 범위와 검색 레인을 넓혀 다시 조사해야 하며 시민 영향이나 출처 관문을 낮춰 숫자만 채우지 않습니다.

자격 증명이 없으면 Codex Skill이 `news.naver.com` 또는 `n.news.naver.com`을 포함한 웹 검색, 뉴스픽 뉴스 카테고리·실시간 페이지, 원문 검색으로 현재 기사를 수집합니다. 자격 증명이 있더라도 API 결과만 사용하지 않고 NAVER News와 뉴스픽의 현재 화면을 함께 확인합니다. 기사 후보나 추가 교차검증 기사를 찾는 요청에서는 Computer Use를 사용할 수 있을 때 NAVER News와 뉴스픽을 각각 최소 한 번 읽기 전용으로 확인합니다. 뉴스픽에서는 헤드라인·표시 언론사·게시 시간·URL만 일시적으로 확인하고, 원문 언론사 페이지를 다시 찾아 교차검증합니다. 공개 커뮤니티는 로그인 없이 접근 가능한 페이지에서 제목·커뮤니티명·URL만 확인하며, 접근 불가 시 `커뮤니티 신호 미확인`을 표시하고 점수를 주지 않습니다. NAVER·뉴스픽·커뮤니티에서 발견된 항목도 동일한 최신성·이미 다룬 주제·원문·독립 출처 검증을 통과해야 하며, 노출 순서·실시간 순위·댓글·추천·자극적인 표현만으로 우선하지 않습니다. 이 화면들은 후보 발견용일 뿐 사실·인기·여론·이미지 권리의 근거가 아닙니다. Computer Use가 없거나 화면을 읽을 수 없으면 각 도메인 웹 검색으로 계속 진행하고 결과에 `Computer Use 미확인`과 별도의 `NAVER News`·`뉴스픽` 확인 상태를 표시합니다. 확인할 수 없는 채널은 `NAVER News 미확인` 또는 `뉴스픽 미확인`으로 명시합니다. 로그인·폼 제출·다운로드·CAPTCHA·유료벽 우회는 하지 않습니다.

## 프로젝트 생성

프로젝트 생성은 필요한 주제와 결과물 범위가 확인된 뒤 진행합니다.

```bash
python3 scripts/news2shorts.py init \
  --title "뉴스 주제" \
  --source-url "https://example.com/article" \
  --delivery-mode continuous-flow \
  --narration-style cc-helper-conversational \
  --format quick-reveal \
  --hook-type result-first \
  --visual-mode hot-real-news
```

생성된 `sources.json`, `fact-sheet.json`, `script.md`, `storyboard.json`, `rights-manifest.json`, `publish.json`을 채운 다음 검사합니다. 한 쇼츠 안에서 동일한 정지 이미지 경로를 두 장면에 사용하면 검증이 실패합니다.

원본 영상 대사를 사용하는 장면은 `audio_mode: "source-video"`로 지정하고 `narration`에 실제로 들려야 할 대사를 기록합니다. 가능하면 미리 자른 조각 대신 승인된 원본 전체 영상을 프로젝트 안에 보관하고 `video_start`와 `duration`으로 구간을 선택합니다. 렌더 전에는 전사 검토를 실행합니다.

```bash
python3 scripts/news2shorts.py review-source-audio \
  --project-dir ./outputs/날짜/프로젝트 \
  --backend auto
```

`auto`는 이미 설치된 로컬 OpenAI Whisper CLI와 캐시된 모델만 사용합니다. 플러그인은 ASR이나 모델을 임의로 설치·다운로드하지 않습니다. 모델 다운로드를 허용할 때만 `--allow-model-download`를 명시합니다. 로컬 전사기가 없으면 장면별 `scene_id`, `text`, 선택적 `segments`를 담은 승인된 UTF-8 JSON을 전달할 수 있습니다.

```bash
python3 scripts/news2shorts.py review-source-audio \
  --project-dir ./outputs/날짜/프로젝트 \
  --transcript-file ./source-transcript.json
```

결과는 `source-audio-review.json`에 저장됩니다. 음원이 바뀌거나 `video_start`, `duration`, 예상 `narration`이 바뀌면 이전 검토는 무효입니다. 누락·불일치·컷 경계 위험은 초안에서 경고하고 최종 렌더에서 차단합니다. 전사는 들린 발화만 확인하며 화자의 신원이나 발언의 사실성을 입증하지 않습니다.

새 프로젝트는 project version 17과 `delivery_mode: "continuous-flow"`를 기본으로 사용합니다. 사용자가 음성 없이 직관적인 화면과 BGM을 요청하면 `--delivery-mode visual-first`를 선택합니다. continuous-flow는 12~35초, visual-first는 CTA를 포함해 8~14초입니다. `shorts_profile.first_answer_scene_id`는 continuous-flow 8초, visual-first 1.5초 안에 시작해야 하며, `truth_guard`가 있으면 `truth_guard_scene_id`가 4초 안에 시작해야 합니다. version 16+는 첫 프레임부터 본문과 좌상단 로고를 함께 표시하고, v15 이하 기존 프로젝트만 저장된 전체화면 인트로를 유지합니다. visual-first는 4~6개 장면, 빈 narration, 장면별 화면 문구와 `claim_ids`, 첫 3초 화면 상태 3개 또는 실제 video를 요구하며 렌더러 생성 무보컬 `news-pulse`를 사용합니다. 정지 이미지는 `image_fit: "auto"`가 기본이라 원본 전체를 증거 안전 영역에 보존하고 남는 공간은 같은 이미지의 어두운 블러 배경으로 채웁니다. 의도적인 전체 화면 크롭만 `cover`로 지정합니다.

중간 구독 CTA 포함 여부는 프로젝트 생성 시 선택할 수 있습니다. 생략하면 `auto`이며, 사용자의 명시적 포함·제외를 각각 `enabled`, `disabled`로 보존합니다.

```bash
python3 scripts/news2shorts.py init \
  --title "뉴스 주제" \
  --delivery-mode continuous-flow \
  --mid-cta-mode enabled
```

`auto`와 `enabled`는 20초 이상 continuous-flow의 40~60% 구간에서 `rehook` 또는 `turn` 경계를 TTS 생성 전에 찾습니다. 선택되면 CTA 전 본문과 CTA 후 본문을 Typecast 두 요청으로 나눠 완전한 문장 끝과 시작을 보존하고, 그 사이에서만 짧은 구독 요청을 말합니다. 화살표는 YouTube Shorts 하단 왼쪽의 채널·구독 영역을 가리킵니다. 가짜 클릭 버튼과 별도 SRT는 만들지 않으며, 검증되지 않은 조회수·시청자 수·구독률 문구를 거부합니다. `disabled`는 조건과 관계없이 중간 CTA를 만들지 않습니다.

시각 자료는 소유 자산, 명시적 재사용이 가능한 공식 자료, 퍼블릭 도메인, 상업 이용 조건이 맞는 라이선스 자산을 먼저 찾습니다. 새 영상은 장면의 60% 이상을 권리와 기사 연관성을 확인한 실제 사진·영상으로 구성하고 비합성 실제 뉴스 사진을 최소 1장 사용해야 하며, 충족하지 못하면 최종 렌더가 중단됩니다. 정확한 숫자와 조건은 관련 실사 위에 자막으로 올리고, 사진으로 설명할 수 없는 근거에만 문서·도표·픽토그램을 사용합니다. 기사에 사진이 보인다는 사실만으로는 사용 권리가 생기지 않습니다. 핵심 기업이 실명으로 등장하면 뉴스 매체명이나 단순 비교 대상을 제외하고 기업 목록과 첫 주요 언급 장면을 기록합니다. 해당 장면에는 실제 로고, 공식 브랜드 이미지, 라이선스 기업 사진, 브랜드 제품 또는 식별 가능한 시설 사진 중 하나를 권리 확인 후 사용합니다. 공개된 회사 홈페이지나 보도자료 로고는 그 자체로 재사용 허가가 아니며, AI로 기업 로고를 다시 그리거나 유사 로고를 만들지 않습니다. 사용 가능한 자료가 없으면 일반 업종 사진으로 바꾸지 않고 최종 렌더를 중단해 권리 장애를 알립니다. 모든 자산은 `relevance_level`과 구체적인 `relevance_note`를 기록하고, 훅·근거·반전·영향·결론 장면에는 실제 인물·사건·대상·문서·메커니즘과 직접 일치하는 자산만 사용합니다. 도시 풍경이나 업종 분위기만 맞는 이미지는 맥락 장면 외에는 허용하지 않습니다. 새 프로젝트는 반응 밈, 대비 합성, 영향 사진, 근거 클로즈업, 동작 증거 중 하나를 핵심 시선 장치로 지정하고 적용 장면과 이유를 기록합니다. 비민감 뉴스의 맥락·재후킹에는 상업 이용 권리가 확인된 반응 밈 또는 직접 만든 밈 카드를 전체 장면의 약 20% 이하로 사용할 수 있지만, 팩트 증거로 취급하지 않습니다. 영화·방송·유명인·SNS 캡처는 인기가 있어도 사용 권리가 아니므로 명시적 상업 이용 허가 없이는 쓰지 않습니다. 생성이 필요한 경우 프로젝트 안에서는 현실적인 편집 사진풍 또는 평면 픽토그램 중 하나를 선택하고, 네온·홀로그램·로봇·광택 3D 아이콘 같은 전형적인 AI 이미지는 피합니다. 생성 파일은 글자·숫자·로고를 이미지 안에 넣지 않고 왜곡, 중복 물체, 깨진 형태와 잘못된 크롭을 육안으로 확인한 뒤 승인합니다. 생성 파일과 권리 기록을 만든 다음 720x1280 이하로 정규화합니다.

```bash
python3 scripts/news2shorts.py optimize-images \
  --project-dir ./outputs/날짜/프로젝트
```

```bash
python3 scripts/news2shorts.py validate --project-dir ./outputs/날짜/프로젝트
```

저작권 상태가 확인되지 않은 공개 이미지는 `kind: "unreviewed"`, `approved: false`, `local_review_only: true`로만 기록할 수 있습니다. 출처와 기사 연관성을 확인한 로컬 검토본에는 사용할 수 있지만 게시 가능한 최종본에는 사용할 수 없습니다.

Whiteboard 옵션은 실제 뉴스 이미지의 권리 상태를 그대로 상속해 선화 장면을 준비합니다. 각 원본의 문자·로고 영역을 확인해 `whiteboard_text_free_reviewed: true`를 기록한 뒤 실행합니다.

```bash
python3 scripts/news2shorts.py collect-internet-visual \
  --project-dir ./outputs/날짜/프로젝트 \
  --scene-id scene-01 \
  --image-url "https://cdn.example.com/photo.jpg" \
  --source-page "https://publisher.example.com/article" \
  --permission-status review_required \
  --relevance-note "기사 당사자가 현장에서 조치 결과를 확인하는 장면" \
  --confirm-news-relevance \
  --confirm-whiteboard-text-free

python3 scripts/news2shorts.py prepare-whiteboard \
  --project-dir ./outputs/날짜/프로젝트

python3 scripts/news2shorts.py render \
  --project-dir ./outputs/날짜/프로젝트 \
  --visual-mode whiteboard \
  --draft \
  --confirm-whiteboard-review
```

결과는 `whiteboard-project/outputs/preview.mp4`에 생성됩니다. 명시적인 장면·annotation 확인 후 화면의 검토 배지는 표시하지 않지만, 프로젝트와 권리 기록의 `publish_blocked`, `local_review_only` 상태는 유지합니다. 이 옵션은 Whiteboard Shorts의 로컬 검토 렌더러를 사용하므로 표준 뉴스한면 인트로와 Typecast 내레이션은 포함하지 않습니다.

## 렌더링

승인 전에는 `preview.mp4` 미리보기를 생성합니다. version 16+는 첫 뉴스 프레임 좌상단에 기존 뉴스한면 로고를 겹쳐 표시하며 인트로 시간이나 오디오를 추가하지 않습니다. v15 이하 기존 프로젝트는 저장된 3.15초 인트로와 전환을 그대로 사용합니다. 완성된 결론 뒤에는 CTA를 한 번 붙이며 v16 기본 길이는 2초입니다. v17에서 중간 CTA가 선택되면 끝 CTA는 구독을 반복하지 않고 0.8초 음성 없는 브랜드 마감으로 바뀝니다. continuous-flow는 짧은 CTA 음성을 사용하고 visual-first는 같은 무보컬 BGM 아래 무음 CTA를 사용합니다. `render-report.json` version 5에는 실제 답변·조건 시작 시각, 중간 CTA 선택·배치·화살표 목표, 끝 CTA와 생성 BGM 정보가 기록됩니다.

기본 20초 Typecast 영상은 반복 설명을 줄여 장면 순서와 답변 시점을 우선합니다. 검증기는 합성 전 예상 길이와 렌더 후 실제 답변·조건 시작 시각을 확인합니다. `신청` 같은 단어 하나만으로 안내형 보이스를 선택하지 않습니다.

영상 결과를 전달할 때는 영상 경로만 반환하지 않습니다. 렌더러는 영상 프레임을 고르는 대신 서로 다른 권리 승인 뉴스 이미지 2~3장을 강한 대비로 합성해 질문형 `thumbnail.jpg`를 별도로 만듭니다. 일반 비민감 뉴스에서 권리와 비당사자 맥락을 확인한 별도 진행자 이미지가 있으면 화면 한쪽에 진행자를, 다른 쪽에 직접 뉴스 근거를 배치합니다. 진행자 자산이 없거나 민감 뉴스이면 직접 근거 합성으로 자동 전환합니다. 주제별 긴장 배지, 질문, 검증된 숫자·조건·시민 영향을 함께 쓰고 결론의 한 부분만 남기되 의미를 바꾸는 조건은 숨기지 않습니다. `충격`, `속보`, `이게 맞아?` 같은 일반 배지는 거부합니다. 원본 해상도가 낮아도 쇼츠 화면에서 질문과 대상이 선명하면 사용할 수 있으며 출력은 기본 720x1280입니다. `publish.json`의 기본 제목 뒤에는 우선 태그 최대 2개가 해시태그로 자동 추가되며, 합친 제목은 100자 이내로 검증합니다. 전체 복사용 태그 목록에도 각 항목 앞에 `#`을 자동으로 하나씩 붙입니다. 설명은 제목을 반복하지 않고 검증된 답·근거·조건·확인사항부터 시작하며 해시태그는 넣지 않습니다. 링크, 사진 제공처·라이선스·자료사진 여부와 Typecast·TTS·합성음성 같은 제작 내부 문구도 공개 설명에서 제외합니다. 해당 정보는 `rights-manifest.json`, `render-report.json`, `contains_synthetic_media`, `altered_content`에만 유지합니다. 그 밖의 태그, 실제 썸네일 파일, 썸네일 훅·보조 문구·배지·구성, 재생목록, 시청자층, 카테고리, 언어, 합성 콘텐츠, 유료 프로모션, 연령 제한, 댓글, 공개·예약 상태와 고정 댓글을 `YouTube 업로드 정보`로 모두 표시합니다. 근거로 채울 수 있는 값을 `미작성`으로 내보내지 않으며, 필수 문구나 업로드 결정이 비어 있으면 formatter가 오류를 반환합니다. 권리 때문에 썸네일 같은 외부 자산이 막힌 경우에만 구체적인 차단 상태와 필요한 입력을 표시합니다. 플러그인이 YouTube에 직접 업로드·예약·게시하거나 댓글을 게시하지는 않습니다.

영상과 무관하게 썸네일만 다시 만들 때는 다음 명령을 사용합니다.

```bash

  --overwrite
```

```bash

```


Typecast를 쓰지 않는 개인 검토본은 macOS 로컬 음성을 명시적으로 선택합니다.

### CapCut/Vrew 편집 호환 패키지

모든 렌더는 완성 MP4와 함께 `edit-package/<출력명>/`을 자동 생성합니다. 기본 미리보기는 `edit-package/preview/`, 최종본은 `edit-package/short/`에 저장됩니다.

- `reference.mp4`: 플러그인의 완성 화면 비교용
- `editable.mp4`: 인트로·음성·장면 타이밍·CTA를 유지하고 뉴스 고정 문구를 제거한 편집용 영상
- `captions.srt`: 인트로 전환 오프셋과 실제 장면 길이가 반영된 UTF-8 내레이션 자막
- `scenes/`, `audio/`: 장면별 MP4와 48kHz WAV
- `overlays/`: 현재 레이아웃을 다시 얹을 수 있는 투명 PNG
- `timeline.csv`, `edit-manifest.json`: 장면 ID, 시작·종료 시각, 문구, 파일 연결 정보

CapCut Desktop/Web에서는 `editable.mp4`를 먼저 가져오고 `captions.srt`를 자막으로 불러옵니다. Vrew에서도 `editable.mp4`로 프로젝트를 만든 뒤 해당 버전의 자막 파일 불러오기 기능으로 `captions.srt`를 적용합니다. 화면을 플러그인 결과와 가깝게 유지하려면 `overlays`의 PNG를 해당 장면 위에 배치합니다. PNG 안의 글자는 래스터이므로 문구를 직접 수정하려면 PNG를 숨기고 SRT 또는 `timeline.csv`의 문구로 새 텍스트 레이어를 만듭니다. 외부 편집 결과는 `storyboard.json`으로 자동 반영되지 않습니다.

## 주요 제한

- 기사 검색 결과의 이미지에는 자동 사용 권한이 없습니다.
- 새 영상은 권리·비합성·기사 연관성이 확인된 실제 뉴스 사진이 없거나 실제 사진·영상 장면이 60% 미만이면 최종 렌더할 수 없습니다.
- 웹 검색 이미지와 영상은 원문 페이지의 상업 이용·수정 조건과 출처를 확인한 뒤 `assets/collected/`에 저장합니다. 사용할 수 있는 결과가 없을 때만 생성 이미지로 전환합니다.
- 일반 뉴스는 두 개, 민감 뉴스는 세 개의 독립 출처를 기본 기준으로 사용합니다.
- 생성 이미지는 권리 매니페스트, `synthetic` 상태, 육안 품질 확인 상태를 기록합니다. 화면에는 `AI 재현 이미지` 배지를 그리지 않으므로 실제 사건 사진처럼 오인될 현실적 재현은 제외하고, 설명형 픽토그램·도표를 우선합니다.
- 이 MVP는 영상을 외부 서비스에 업로드하지 않습니다.
